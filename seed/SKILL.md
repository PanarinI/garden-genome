Ты проводишь ГЕНЕЗИС — из генома (этого закона) зачинаешь новый живой организм-проект
ЛЮБОГО рода (не только код): разворачиваешь самоподдерживающийся живой контекст. Если
пользователь указал тему (в сообщении или после /seed) — используй её как стартовую подсказку.

# Шаг 1. Расспроси про СУТЬ — по-человечески, не анкетой
Задавай 1–2 вопроса за раз. Собери Charter: что это (одно предложение) · зачем/цель ·
готово-когда · ограничения · не-цели.
ВАЖНО: Charter — ЖИВАЯ ГИПОТЕЗА, не контракт. «Пока не знаю» — валидный ответ; пустое поле
— тоже сигнал (тут туман). Не выдумывай за пользователя. Для творческих/исследовательских
проектов «готово-когда» и «не-цели» можно осознанно отложить. Charter пересматривается на шаббате.

# Шаг 2. Услышь, что будет расти (НО НЕ создавай органы)
Из сути проекта спроси себя: *какое знание здесь будет накапливаться — и куда оно не влезет
в три столпа?* Назови 1–2 вероятных органа как гипотезу — не создавай. Это приглашение, не
предписание. Органы рождаются ПОЗЖЕ и только по нужде (YAGNI).

# Шаг 3. Заведи папку проекта и разверни позвоночник
Придумай короткое kebab-имя латиницей по сути и создай НОВУЮ папку `~/PycharmProjects/<имя>/`
(по умолчанию новые проекты Igor живут там). Исключение: если ты уже в пустой папке под
этот проект — разворачивай прямо в ней. Создай три файла: `CLAUDE.md` (зерно ниже с Charter
и картой), `STATE.md` («Фаза: старт. Следующий шаг: …»), `DECISIONS.md` (журнал/первое решение).
Назови папку (легко переименовать), покажи, что создал, выдай первый «следующий шаг».
Работать можно сразу — обращайся к проекту по полному пути; ручного переключения папки не требуется.
Одной строкой укажи (не пересказывая): ритуал выдоха живёт в CLAUDE.md §3 и запускается
скиллом `/shabbat`. Организм дальше дышит сам — твоя работа как семени окончена.

## Содержимое для CLAUDE.md (подставь Charter и карту):

~~~markdown
# <Проект> — живой контекст (Project DNA)

> Зерно проекта: само себя выращивает. Читать в начале сессии, обновлять в конце
> (шаббат). Держать маленьким и честным.

## 1. Суть (Charter) — живая гипотеза, не контракт
(«пока не знаю» — ок; пересматривается на шаббате)
- Что это: …
- Зачем / цель: …
- Готово, когда: …
- Ограничения: …
- Не-цели: …

## 2. Столпы (живая карта)
Позвоночник: этот файл (суть+правила) · STATE.md (где мы) · DECISIONS.md (почему).
Органы (растут по нужде): —

## 3. Протокол роста — дыхание организма
- Вдох (старт сессии): читать этот файл → STATE → DECISIONS → нужные органы.
- Обмен веществ (всегда): любую входящую мысль направляй — устоявшееся/структурное → в столп;
  накапливающееся знание → в орган; сырое → держи в живом контексте. Всегда говори, куда положил.
- Рост: инфа повторяется и не влезает в столпы → предложи орган (имя+зачем), рождай с «да».
- Выдох (шаббат): обнови STATE; допиши «почему» в DECISIONS; поправь этот файл при смене сути/карты;
  пересмотри столпы (родить/слить/убрать); выдай «первое сообщение для новой сессии».

## 4. Законы курирования
Весь закон висит на двух: **возлюби суть** (сигнал, не лог) · **возлюби того, кого тут не было**
(пиши для следующей сессии). Производные: один факт — один дом · стабильное ≠ волатильное ·
структура по весу (YAGNI) · рост вглубь, не вширь (новый принцип вытесняет, не добавляется) ·
столпы малы — читаются на одном дыхании · имена папок/файлов/команд — латиницей · доки в git.
~~~
