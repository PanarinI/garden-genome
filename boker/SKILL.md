Ты делаешь BOKER — ритуал начала сессии (утро после шаббата). Цель: восстановить контекст сада и продолжить
с того места где остановились, без лишних вопросов.

# Шаг 1. Читай сад

Прочитай по порядку:
1. `~/PycharmProjects/CLAUDE.md` — топология сада
2. `~/PycharmProjects/garden-meta/atlas/MAP.md` — карта всех проектов
3. `~/PycharmProjects/garden-meta/atlas/STATE.md` — открытые узлы и следующие шаги

**Проверь свежесть карты — но НЕ обновляй её** (это разные действия):
- **Не переписывай MAP на вдохе** — синк карты это работа «обхода» (решение 2026-06-29), не boker.
- **Но сделай дешёвую проверку (одна команда):** сравни дату `MAP.md` с самым свежим `*/STATE.md`
  (напр. `ls -lt garden-meta/atlas/MAP.md */STATE.md`). Любой STATE новее MAP → карта отстала:
  **скажи честно, доверяй свежим STATE проектов (это истина), а не сводке в MAP,** и предложи «обход»
  для полного снимка. MAP свежее всех STATE → панораме можно верить.

Почему так (постижение 2026-06-30): MAP — производный снимок и протухает (шаббат правит STATE проекта,
но не MAP). Раньше boker запрещал даже *проверять* свежесть — и однажды прочитал карту суточной
давности, проглядел новорождённый проект и соврал про активную нить. **Проверка ≠ синк:** проверка
почти бесплатна и спасает от слепого доверия; тяжёлый синк (перечитать все STATE + переписать MAP)
остаётся за «обходом».

# Шаг 2. Разбери ведро (INBOX) — запусти ритуал «разбор»

Прочитай `~/PycharmProjects/garden-meta/INBOX.md` (из облака — `INBOX.md` в корне репо).
Пусто под линией → иди дальше. Есть записи → выполни **ритуал «разбор ведра»** (описан в
`garden-meta/CLAUDE.md`): каждую запись разложи по дому и скажи куда; **разобранное перенеси в
`INBOX-archive.md`** (append, с датой) — НЕ удаляй; `INBOX` оставь чистым для захвата.
(Разбор — отдельный опер-ритуал, boker его лишь запускает; его же можно позвать словом «разбери ведро».)

# Шаг 3. Найди активный контекст

Определи, какой проект был активным последним. **Если проверка в Шаге 1 показала, что MAP отстал —
бери активную нить по самым свежим `*/STATE.md` (`ls -t`), а не по тексту MAP** (иначе сядешь на
протухшую карту). Смотри на даты STATE.md и пометки "в работе". Прочитай свежий STATE этого проекта.

Если в предыдущем шаббате было "первое сообщение для новой сессии" — это твой главный ориентир.
